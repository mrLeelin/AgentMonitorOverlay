# AMO Host 改动说明

## 下一版

- 机器人主控启动时明确引导发现并调用 AMO 派工、验收工具，实际调用失败时报告原因。Plane 主控未提交当前批准计划的交付时，首轮停止后仍留在进行中；启动恢复会纠正旧的误进待审阅。检查原项目未提交改动时，提示执行者从批准的原目录只读取证，避免把独立工作树误当成原项目现场。

- Plane 工单支持按批准计划建立专属主控根。执行任务使用独立工作树，接入前置改动后才开工。项目或基准变化须再次批准，根交付人工通过后按原单和版本核对评论回执。原独立工单继续走原执行和验收入口。

- 主控由任命的机器人接手。中控须选择与上下级不同的机器人，换任保留任务、画布、交付和原会话。旧主控树可从任务或专题画布选择「绑定机器人」，历史完成项沿用原记录。旧客户端的无机器人主控请求会提示更新 Studio 并选择负责人。

- 共同需求任务的前置交付换版后，直属主控可用「重新开始」按新验收版本在原任务开工。旧会话和交付依据仍可查，相同重开请求复用回执。Host 在 Codex 首轮发送前中断时，重启可从同一会话继续。首轮已附带共同需求时，等待 Codex 确认收到，避免单独再发一轮相同正文。首轮送达不明时，回执会提示打开关联会话核对。

- Bot 普通聊天在收到首条消息时创建，重复发送同一次尝试会复用原会话。Bot 侧栏可读取各聊天的近期消息摘要。

- Codex 程序缺失或无法执行时，主控卡和接单回执直接显示出错的程序及原因。修复启动配置后可在原卡重试同一任期。
- 本地 Bot 请求、专题和普通任务可任命机器人主控。接单保存专题、主控卡和任期后启动只读会话，同一请求在执行和带队入口只承接一次。普通任务等原会话和待发消息处理后交接，启动失败可在原卡重试。

- 会话消息可排进持久队列，等正在运行的回合结束后按顺序各开一轮。单条消息仍可通过「立即发送」提前送出。

- 修复 Claude 订阅（本机登录）拿不到 Claude Code 的真实型号列表：查型号时用的工作目录 `claude-home` 只在 token 登录时才建，不存在时 Claude Code 起不来，型号一直退回内置列表，Opus 也不显示 Fast。现在查型号前先建好这个目录。

- 新增 `GET /api/sessions/:id/context-usage`：Claude 会话从运行中的进程读上下文分项和说明文件（getContextUsage，summary 级别，不额外计数），进程退出后返回上一次的结果；其他模型返回原因。新增 `POST /api/sessions/:id/mcp/:name/reconnect`：Claude 会话单独重连一个 MCP，不写配置文件，重连后刷新状态。

- 新建任务可用 Codex、Claude、DeepSeek Harness 或 Pi 在独立 Git 工作树中启动。首条消息、后续消息和恢复会话都使用该工作目录。

- 按渠道保存隐藏的型号，新会话默认使用可见型号，保留已有会话原有的型号和选项。

- 总主控的普通追问、通知和会话收尾不再撤销已提交或人工验收的交付；人工验收后可在待审阅与完成间拖动。明确重开、新增未完成下级、下级继续工作、转交及依赖失效仍使旧交付失效，AI 仍不能自审或直接完成管理任务。人工审核另保存原始结论、意见与时间，后续失效仍可追溯，不推断或修补旧数据的验收来源。

- 技能展览新增只读目录接口，按全局或已登记项目扫描多个工具的技能和插件缓存，返回名称、描述、真实路径及诊断；支持链接去重、防循环和读取限制。

- 主控新增 `task_workflow` 精简全树核对（`view: summary`），显示最新交付有效性、实际前置、当前等待和会话记录创建时间；新增 `task_read_result` 按结果分页读完整证据，保留原有 full/pending 调用。角色说明与依赖启动提示明确集中取证、引用上游结果和按需复核，减少重复全量读取及逐层复制。

- 交付汇总兼容通知正文冻结：后续交付加入待送汇总时，以新通知替代旧行并保留来源；部分交付已处理时仍保留其余交付的有效通知，最终交付继续由用户验收。

- 总主控提交最终交付后保持待审阅，等待用户在 Studio 明确验收或退回，禁止 AI 自审或通过普通状态修改跳过；二级主控和执行任务仍交直属主控验收。用户审核保存来源与意见，退回经持久收件箱继续；重开和转交使旧交付失效，通知回复保留有效验收。

- 修复 Pi 在发送、重发或启动回合期间消息失效后被改回「未发送」的问题，保留永久过期状态、原文和失效原因。
- 画布自动回传按新消息替代旧待送结论，保留替代来源与未送达的角色说明；撤回结论永久过期，不复用或改写旧消息。

- Pi 的会话 MCP 兼容 `pi-mcp-adapter`：在扩展加载后优先使用其运行时注册接口，无适配器时沿用 Pi 原生接口；退出时清理注册，不写入用户配置。

- DSH 创建或恢复会话时，如果额外 MCP 连接失败，明确显示服务名称及检查、关闭入口，避免只报「Internal error」而误以为 API Key 失效。

- 增加维护页 CLI 版本检测与后台更新接口，按本机 Claude Code、Codex、Pi 的安装方式执行更新，更新后复核版本，保留失败原因；Pi 按本机实际安装的 npm 包检查和更新，不改写 SDK 自带副本或重启 Host。

- 新增 Pi RPC 运行时，沿用本机 Pi 配置，会话保存在 Studio 数据目录；支持消息、图片、工具、用量、压缩、扩展问答和按会话注入 MCP。严格按回合完成事件收束，待送消息重核有效性，明确拒绝 Pi 无法兑现的只读和沙箱权限。

- 修复管理通知生命周期：过期与撤回保存永久终态，保留冻结正文、原因及替代来源；显式升级只重建同树仍有效业务，历史作废通知在状态变化与 Host 重建后不复活。旧失效行经正式服务兼容，真实发送失败保留具体原因及重试入口。
- `task_message` 新增结构化 `purpose`（`inquiry` / `work` / `reopen`），缺省保持原派工行为；用途持久传入实际运行回合，只读询问及自动状态通知保留验收，明确继续工作仍重新验收。询问保持管理归属、共同需求和依赖检查，并限制写工具及运行时写权限。
- 自动传话等待任务正在创建的主会话，不同传话共用首会话创建，避免与依赖自动启动同时打开两个执行者；等待后重新检查任务归属，创建失败可重试。首次会话初始化覆盖状态更新，避免重复排入共同需求通知。
- `task_get` 返回保留换行的完整任务说明，角色卡预览标明读取入口；派工提示要求传齐执行契约，减少说明截断后的补发往返。
- 执行者在同一回合提出业务问题后，正常结束时不再重复发送本轮状态；问题通知和答复照常传递，故障、中断及后续普通回合仍上报，旧版重复状态在投递和重试前失效。

- 下级主控结束普通进度回合时不再自动唤醒上级，避免派工后或验收间反复空查工作流；正式交付、业务问题、主动传话及故障和中断上报保留。旧版排队的主控普通进度通知在投递与重试前失效。

- 主控可用 `task_workflow` 的 `pending` 视图读取各任务最新待处理交付、失效交付及待决问题，减少重复读取已验收历史；完整历史仍通过 `full` 视图读取。
- 自动启动依赖任务时，在首次消息附上对应前置的已验收摘要、验证证据及结果 ID，减少执行任务查找前置内容的往返。

- 下级交付会合入主控尚未收到的汇总通知，逐项验收仍保留；发送与手动重试前重新核对结果和归属，收件箱等待后重新读取消息状态，避免旧通知重新唤醒已完成的任务。
- 待办任务首次带工作内容开启会话后自动进入进行中，空会话仍保留待办状态。

- 主控自动派工成功时，结果已由工具直接返回，不再把重复的成功通知排进会话；主控无其他独立工作时结束回合，等待下级交付或问题自动唤醒。
- 下级普通回复超过 6000 字符时明确提示截断，并允许直属主控用 `task_read_reply` 分页读取原文；任务转交后旧主控不再拥有读取权限。

- 修复隔离 Host 重建或 Codex 重新连接后，第一次继续可能先于线程恢复而报「thread not found」：同一连接的恢复由等待者共享，完成恢复后才允许发送，不要求用户重试；原收件箱暂停、稳定通知和消息内容保留。

- 增加显式管理树共同需求：可编辑草稿、冲突检查、不可变发布版本，以及按受影响任务单独绑定和升级；完成历史任务保留原依据，普通专题文档不变。
- 增加 `context_get/save/publish/apply/adopt` 工具及 HTTP 接口，三种运行时统一接收冻结正文；排队、传输送达和执行者声明采用分别记录。更新复用持久收件箱、稳定去重及用户停止状态，转交后旧需求通知失效。
- 交付记录实际需求版本和具体前置 resultId；差异成果可先保存，接受前须显式处理，事务内重新核对要求及归属。自动与已绑定任务直接启动检查前置真实验收和有效依据，旧未绑定任务兼容。
- 共同需求正文按业务 JSON 数据传入，不能改变角色和工具权限；实际版本须存在且曾向该交付任务会话完整提供，伪造、跨树及无效前置依据不能用差异说明豁免。根主控可在当前回合内处理自身差异交付，其他在途会话仍需先结束。
- 共同需求首次及新绑定版本提供完整正文，同一会话送达后的后续回合只附版本引用和读取入口，避免反复注入全文；需要恢复正文时可用 `context_get` 完整读取。轻量引用不伪造正文提供或采用，已排队文本继续冻结。
