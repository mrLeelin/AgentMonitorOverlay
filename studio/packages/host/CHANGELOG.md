# AMO Host 改动说明

## 下一版

- 总主控提交最终交付后保持待审阅，等待用户在 Studio 明确验收或退回，禁止 AI 自审或通过普通状态修改跳过；二级主控和执行任务仍交直属主控验收。用户审核保存来源与意见，退回经持久收件箱继续；重开和转交使旧交付失效，通知回复保留有效验收。

- 修复 Pi 在发送、重发或启动回合期间消息失效后被改回「未发送」的问题，保留永久过期状态、原文和失效原因。
- 画布自动回传按新消息替代旧待送结论，保留替代来源与未送达的角色说明；撤回结论永久过期，不复用或改写旧消息。

- Pi 的会话 MCP 兼容 `pi-mcp-adapter`：在扩展加载后优先使用其运行时注册接口，无适配器时沿用 Pi 原生接口；退出时清理注册，不写入用户配置。

- DSH 创建或恢复会话时，如果额外 MCP 连接失败，明确显示服务名称及检查、关闭入口，避免只报「Internal error」而误以为 API Key 失效。

- 增加维护页 CLI 版本检测与后台更新接口，按本机 Claude Code、Codex、Pi 的安装方式执行更新，更新后复核版本，保留失败原因；Pi 按本机实际安装的 npm 包检查和更新，不改写 SDK 自带副本或重启 Host。

- 新增 Pi RPC 运行时，沿用本机 Pi 配置，会话保存在 Studio 数据目录；支持消息、图片、工具、用量、压缩、扩展问答和按会话注入 MCP。严格按回合完成事件收束，待送消息重核有效性，明确拒绝 Pi 无法兑现的只读和沙箱权限。

- 修复管理通知生命周期：过期与撤回保存永久终态，保留冻结正文、原因及替代来源；显式升级只重建同树仍有效业务，历史作废通知在状态变化与 Host 重建后不复活。旧失效行经正式服务兼容，真实发送失败保留具体原因及重试入口。
- `task_message` 新增结构化 `purpose`（`inquiry` / `work` / `reopen`），缺省保持原派工行为；用途持久传入实际运行回合，只读询问及自动状态通知保留验收，明确继续工作仍重新验收。询问保持管理归属、共同需求和依赖检查，并限制写工具及运行时写权限。
- 修复隔离 Host 重建或 Codex 重新连接后，第一次继续可能先于线程恢复而报「thread not found」：同一连接的恢复由等待者共享，完成恢复后才允许发送，不要求用户重试；原收件箱暂停、稳定通知和消息内容保留。

- 增加显式管理树共同需求：可编辑草稿、冲突检查、不可变发布版本，以及按受影响任务单独绑定和升级；完成历史任务保留原依据，普通专题文档不变。
- 增加 `context_get/save/publish/apply/adopt` 工具及 HTTP 接口，三种运行时统一接收冻结正文；排队、传输送达和执行者声明采用分别记录。更新复用持久收件箱、稳定去重及用户停止状态，转交后旧需求通知失效。
- 交付记录实际需求版本和具体前置 resultId；差异成果可先保存，接受前须显式处理，事务内重新核对要求及归属。自动与已绑定任务直接启动检查前置真实验收和有效依据，旧未绑定任务兼容。
- 共同需求正文按业务 JSON 数据传入，不能改变角色和工具权限；实际版本须存在且曾向该交付任务会话完整提供，伪造、跨树及无效前置依据不能用差异说明豁免。根主控可在当前回合内处理自身差异交付，其他在途会话仍需先结束。
- 共同需求首次及新绑定版本提供完整正文，同一会话送达后的后续回合只附版本引用和读取入口，避免反复注入全文；需要恢复正文时可用 `context_get` 完整读取。轻量引用不伪造正文提供或采用，已排队文本继续冻结。
