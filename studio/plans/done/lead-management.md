# 主控归属与画板关系

用户决定（2026-11-07）：管理必须有持久归属，不能按同专题、位置或普通线文字推断权限。主控保留本地文件只读，实施放在独立执行任务。不得重启正在使用的 Studio/Host，不自动提交或发布。

任务的 `managerTaskId` 是可空单一直属上级。迁移不猜测旧任务归属；有专题时须同专题，无专题时须同项目。上级须有效本地主控，禁止自管、环及无效祖先链。`taskManagement` / `isManagedBy` 统一查询、去重统计和权限判断；根主控读取完整下辖树。协作和引用只表达关系，不扩权。

用户通过任务页或画布详情设置、转交、解除归属；专题会话可完成本专题首次分配，主控只在已有下辖树内转交，不能认领平级或自设上级。HTTP 用户入口可信，MCP 在每次调用时复查身份和范围；画布写入先检查差异涉及的卡片、分组成员及线端点，拒绝后不写入。`task_manager_set`、`task_management` 分别负责归属变更和读取；PATCH 任务与 GET management 提供相同 UI 接口。

提案保留 `fromTaskId`，接受前验证来源仍有效；创建时将归属和说明一起持久化，之后才启动首会话。用户修改提案不会悄悄丢掉来源主控。来源失效时要求重新提案。专题会话的提案没有来源主控，保持未分配。

生命周期采用显式处理规则：有上下级归属时先解除/转交再跨管理范围移动；有直属任务（含归档）不能取消主控；活跃下属未处理时不能单独归档主控。专题/项目批量归档先预检、从叶到根，恢复从根到叶；跨项目仍存活的下属会阻止归档其主控所在项目。删除集若仍被保留任务引用，则预检和存储事务都拒绝，不能隐式转交。

管理线由归属派生为有向虚线，不写入依赖或普通链接，不阻塞执行。协作写入独立 `kind: collaboration` 的无向链接，按端点去重，选中相关卡片显示点线。依赖保留有向实线；旧普通线、标签和布局保留。画布提供关系图例与开关、直属主控定位、选主控高亮下辖、层级折叠；详情展示树、状态、进入任务、分配工作和转交。主控统计使用统一树，待确认摘要合并任务决策与画布提问。显式「按管理层级排列」只排列未分组任务，保留已分组卡片位置与所有关系，避免覆盖用户布局。

转交后重新检查缓存 MCP 工具和待送传话；传话来源随收件箱消息落库，在最终发送、立即发送及重试时复查，Host 重建也不会恢复旧权限。取消主控后旧工具自动批准失效；归档会话、任务或专题不再接受 MCP 写入。
