# 画布审阅的来源与讨论关系

## 用户决定

2026-11-08，用户在专题画布看不到主控和连线，核对实际为普通任务铺出的审阅卡，未设置管理归属或普通连线。用户同意四项一起实施：自动显示来源任务到问题组、卡片优先继续已有讨论、按需展开会话小卡，以及独立的来源与讨论显示开关。

## 做法和原因

- 从审阅卡 `sessionId` 找来源任务，同一来源任务对同一分组只画一条「整理出」线；不同来源分别显示，无分组的条目直接连接。来源任务是主控才显示主控，不自动更改角色或管理归属。
- 来源任务已有任务卡或引用卡时复用；没有时显示紧凑来源入口，点击打开来源会话。来源会话或任务已不存在时保留不可用提示，不伪造归属。
- 审阅卡固定显示讨论入口：有可继续的会话时打开最近使用的未归档讨论，否则展开新讨论。详情里保留明确的「新开讨论」；正在创建同一条目的会话时忽略重复点击。
- 点「讨论 N 个」在卡片旁展开关联会话小卡，同时显示「讨论」连线，可点击进入已有会话。一次展开一张问题卡，收起不删除任何会话；已归档会话标明状态，已不存在会话显示不可用。
- 自动关系从现有数据推导，不写入普通连线，不开放拖动或删除。点划线带文字，与管理、协作、依赖区分；线和文字不拦截鼠标。复用现有避障算法并交换坐标轴，让线从右侧出、左侧入。
- 会话小卡避开手工卡片、分组和其他来源/讨论小卡，仅调整临时展示位置。「全部」适配包含这些小卡的范围。手工卡片本身重叠封死出口时沿用避障算法的回退，不强制移动用户内容。
- 「来源与讨论」开关保存在本机。小窗保留原紧凑显示；新关系在完整画布上查看。用户会话和画布内容都没有在测试中改写。
