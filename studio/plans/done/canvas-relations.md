# 画布连线纠错与管理树布局

## 用户决定（2026-11-07）

- 保留管理、依赖、协作、普通线的类型、含义、创建入口和普通线方向；不加拖线类型弹窗。管理归属仍由任务单上级树决定，汇报使用任务状态、交付和消息。
- 普通线按类型、方向和卡片端点去重，连接点仅决定走线；协作无序去重。普通有向线和依赖各自在自己的图内拒绝自连、双节点环、长环，协作允许三角关系，依赖允许分叉汇合。
- 完整保存、API/MCP、UI 拖线、反向和详情使用同一套规则。版本冲突、归档和管理范围授权继续由 Host 检查，非法保存整份拒绝。
- 不清理真实画板、不推断旧管理归属、不删失不同标签或不同关系。保留现有大量未提交改动，不提交、发布或重启用户实例。

## 做法和原因

`protocol/canvas-relations.ts` 提供可定位问题和增量校验。关系身份不含 side 和 label；比较上次已保存的关系 id、类型和端点，允许旧问题的原样保留、移动、标签编辑及逐条删除，但任何新增或改端点产生的问题都拒绝。不能把“旧图有环”当作拒绝所有新依赖的理由，因此候选防环只检查新增路径的可达性。

Host 完整保存使用数据库中的 current 作为基线，客户端无法自行声明豁免。UI 在持久化前检查，并把路径转为任务标题/便签文字。旧问题面板列出问题路径、具体线 id 和各自标签，支持定位起点、显式删除一条；不会一键合并或静默丢失文字。普通线与依赖右键反向都校验，详情添加也给出同样提示。

管理排列沿用现有按钮：有选中范围时只排该范围的未分组任务，否则排全部未分组任务；按实际卡片尺寸、子树宽度居中、层高和留白排列，避让固定分组和其他卡片。父主控位于固定分组或范围外时，将可动层整体下移到固定上级下方，保留同层对齐。管理折线优先共享分叉横线，遇卡片走侧廊或网格绕行；过滤、选中范围和关系开关不变，不强排依赖图。
