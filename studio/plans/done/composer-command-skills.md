# 输入框快捷指令与技能

状态：做完（2026-11-12）

## 用户定的行为

2026-11-12：会话输入框和新建任务的「第一句话」均要支持 `/` 快捷指令与技能菜单；`$` 只显示可用技能。

同日补充：输入框中出现技能引用时需要高亮，并可点击打开该技能。

## 做法与原因

- 两处共用命令菜单和光标解析。`/` 在消息开头触发，允许前置空白；`$` 可在消息中的独立词位置触发。按当前词过滤，选择技能时保留周围文字并恢复光标；Esc 只关闭当前词的菜单，不屏蔽同一消息里的其他技能引用。
- 会话继续读取 `GET /api/sessions/:id/commands`；第一句话使用 `POST /api/commands`，传入所选 profile 和 workspace，未选项目时读取公共目录。更换项目或模型后重新读取，旧请求结果不显示到新目标。
- 第一句话的菜单只补全，不创建任务、会话或调用模型。Studio 的压缩上下文和打开会话 Review、Codex 原生 review/start 需要已有会话，因此不在首条消息列表里冒充可直接执行的命令。
- Codex 复用原生 skills/list，Claude 通过无 prompt 的原生命令/技能探测，Pi 通过不保存会话的 RPC 查询。DSH 的动态列表依赖已启动会话，启动前明确说明这一限制；无法读取列表时显示原因。
- Codex 首条消息和后续消息中的已知 `$技能`、消息开头的 `/技能` 随原文附带原生技能名称与路径。未知名称保留为普通文字。
- 新建任务的菜单放在输入区下方的文档流里，避免覆盖模型选择；已有会话菜单保持在输入框上方。
- 完整的可用技能引用在两个输入框中显示为可编辑高亮链接；手动输入、选择和恢复草稿走同一套识别，不将变量、路径、未知技能或未补全的名字误当链接。点击或键盘聚焦后按 Enter/空格，在现有查看器打开 `SKILL.md`；原始草稿和发送文字保持原样。
- 命令列表提供可选 `skillPath`。Codex、Pi 采用原生技能路径；Claude 从当前项目、实际配置目录与已安装插件目录查找唯一真实文件，无法可靠定位时明确提示，避免打开同名的错误文件。技能列表更新导致编辑器失焦重绘时保留文本光标，重新聚焦后恢复。

## 验证入口

`e2e/studio/composer-commands.spec.ts` 覆盖两个输入框、两种前缀、项目/模型切换、光标与周围文字保留、Esc、多处引用、发现时不创建会话，以及真实 Codex 程序配合 mock 模型的项目技能发现与首条消息。底层路由、原生技能输入、Claude/Pi 查询和导航锚点另有定向单测。界面截图在 `screenshots/studio/composer-*.png`、`screenshots/studio/newtask-{slash,skills}-*.png`。
