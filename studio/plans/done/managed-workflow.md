# 主控分工、交付与统一沟通

用户决定（2026-11-09）：人只与总主控沟通需求和最终交付；总主控分配给资源、音效、逻辑等负责人，负责人可继续拆分；结果沿直属管理关系逐层返回，主控验收后统一汇报。原画布审阅示例不能代替这条工作流程。

用户明确（2026-11-12）：「主控应该交给我，主控控制的交给主控」。没有直属主控的总主控提交最终交付后，结果保持 submitted、任务保持 review；只有用户在 Studio「交付与验收」明确验收后才 accepted/done，退回则 returned/doing。受管任务（含二级主控）仍必须由直属主控验收或退回，AI 不得自行验收自己的交付。

人工审核使用独立 user-review REST 接口及完整 Host 凭据，不提供 MCP 工具，AI 的 MCP 凭据不能调用。人工按钮保存审核来源、意见和可选需求差异说明；仍校验最新交付、当前归属、全部直属任务、未决问题、会话安定及有效需求/前置依据。拖动待审或已退回的总交付到完成会提示从交付面板审核，普通人工改名、归属、重开和归档保留。重复提交与审核幂等；真实继续工作或转交使旧交付失效并要求重提，普通通知回复、只读询问不清除待审或有效验收。用户退回经持久收件箱作为工作送回总主控，暂停/等待/失败重试沿用现有规则。

历史自动完成的总交付不追认为用户验收，界面显示「历史交付」；不批量改写旧状态，也不擅自加载当前运行的 Host。

复用显式管理树。主控拆任务自动创建并启动，支持二级主控；专题会话的提案仍由人确认。管理归属、角色、范围在首会话前持久化。依赖项须经主控验收完成才启动后续任务。主控仍只读本地文件，不绕过角色权限。

交付使用独立结果记录，包含工作摘要和验证证据。直属主控验收或退回；下辖工作和业务问题未处理时不得逐层交付。会话停止只报告本轮状态，不等于完成。通知经持久收件箱投递，兼容忙碌、手动停止、重启、转交和归档；旧任务不因安装功能而重新执行。

执行任务的 decision_request 先送直属主控，主控解决不了再提出自己的问题逐层上报；总主控的业务问题才直接提醒人。工具原生问答、命令授权和运行故障保留可见，不能隐藏阻塞或自动代批安全授权。画布继续展示管理关系与任务；新建页复用主控选项作为入口。
