# AMO 团队任务

> 状态：首版探索已结束。当前方案见 [独立团队看板](team-board-server.md)。

## 一张原单走完提单到验收

2026-11-24 用户确定自建轻量提单工具。团队任务是独立的 Windows 客户端。同事使用 AMO 平台的团队账号登录，在客户端提单、看进度和验收。接收人在 Studio 看板右侧拖入待办，也可点按钮加入。独立客户端沿用 Electron、React 和 TypeScript，通过平台安装更新。

用户之后明确，同事提单时只选择接收人，团队任务列表按提交或接收查看，暂不按项目分组。接收人在 Studio 打开目标项目后接入，或在收件箱选本地项目。

- 团队服务在现有中转 SQLite 数据库中保存原单和流转记录，附件保存在 `files/team-tasks`。团队任务和附件均按提交人、接收人校验权限。这个产品有自己的表和接口，原有中转任务仍按全队可见的规则运行。
- Studio 保存原单关联、导入时的说明和可编辑的第一条消息。同一团队服务器的同一原单在一份 Studio 数据目录里只对应一张本地任务。拖入不会启动会话。
- 团队状态为「待处理 → 处理中 → 待验收 → 已完成」。发送第一条工作消息后才尝试同步开工。临时连接失败时，可以从任务页的「团队原单」重试同步。发送交付要由人在任务页选择说明和附件，提交人可确认完成或发回继续处理。
- 团队服务负责鉴权、状态流转和冲突检查。附件和动作整批提交，每次最多 6 个，合计 16 MB。两个客户端分别通过中转和本地 Host 读取原单。

## 交付和验证入口

- `npm run team-tasks` 从源码打开独立客户端。用 AMO 平台的账号访问该账号所属的团队服务器，Studio 看板的「团队任务」用同一登录机制。
- 独立客户端打包沿用 `node scripts/package-portable.mjs --platform --only team-tasks`。团队服务器和独立客户端分别走现有的发布流程。
- 隔离验收见 `e2e/studio/team-tasks.spec.ts`，使用真实团队鉴权和 SQLite、两个 Electron 窗口及模拟模型。服务和客户端重开后再检查原单、附件、流转历史和本地关联。服务端的隔离权限、重复提交和过期版本校验见 `packages/relay/src/team-tasks.test.ts`。
