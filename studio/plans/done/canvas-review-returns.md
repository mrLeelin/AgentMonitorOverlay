# 画布确认后自动回传

> 状态：做完（2026-11-09）。Host、界面和隔离 mock Electron 验证完成，开发版已重启加载。

## 用户定的事

2026-11-08 晚至 11-09：分支讨论确认后自动回传主控，不让人再切回主控转述；本轮问题处理完自动通知主控继续。实施范围沿用原任务授权，新的待决问题再回画布。重复确认不重复执行。

## 做法与边界

- 一轮按「同一来源会话 + 同一分组」划分；未分组的同来源条目归一轮。确认、完成、搁置都视为本轮已处理，搁置项不要求实施。
- Host 监听画布保存，UI 改状态和 MCP 写结论走同一套检测；每条新结论写进来源会话的邮箱。整轮收齐才发一条继续通知，要求主控先读最新画布、按已有授权和角色约束组织实施或继续讨论。来源自己写的进度不反过来唤醒自己。
- 回传记录与画布文档分开持久化，拖动和旧窗口保存不会覆盖回执；用内容指纹去重。继续通知先落盘，再通过有固定消息 id 的会话收件箱投递；重启重试复用同一行。
- 来源忙着时消息留在收件箱，后续结论变化以新通知替代未送出的旧通知，旧正文永久过期留档，始终只保留一条有效继续通知。人主动停止的会话保持停止，沿用收件箱的恢复规则。问题重新打开、删除或分组变动使本轮不再收齐时，撤回未送出的通知；已经送入模型的通知要求重新核对最新画布。
- 来源被归档、删除、移出专题或不支持直接接收时显示「回传受阻」，不猜另一个主控；恢复来源后可重试。模型发送失败沿用会话里的「重新发送」。首次加载不自动重启历史已确认工作的执行。
- 卡上显示「已回传主控／来源」；画布上显示本轮通知状态。来源任务并非主控时，不把它标成主控。
