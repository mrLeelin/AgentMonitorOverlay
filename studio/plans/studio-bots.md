# AMO Studio 常驻 Bot

> 状态：进行中。2026-11-25 用户要求迁移 Orca Bots，并在主工程的独立分支提交。实现分支为 `feat/studio-bots`，以本机 Orca 1.4.274 为行为参考。

## 首版体验

在「设置 → 工具与自动化 → Bots」创建或配置「审核员」，选渠道和型号，通过滑杆调整推理强度，通过卡片选择执行权限，填写审核职责和可复用的记忆。回到本机任务会话，输入 `@` 并选择「审核员」，再发送审核要求。原会话显示一条可打开的审核记录，包含进度和结论。点击记录进入同一审查会话看完整结果、停止或继续追问。

审核员默认在发起会话的实际工作目录里检查，以便看到用户指定的 worktree 里的未提交改动。需要审核另一个工程时，从 Studio 已登记的项目中选取。结论按问题严重程度列出文件、行号和证据，并注明检查范围和未验证项。

2026-11-26 用户给出侧栏和创建交互参考。Bots 放在左栏独立区域，主聊天由 Bot 自己的入口打开，工作者仍是可执行的项目任务。折叠、排序和筛选保存在当前窗口。加号支持空白、模板、Orca 分享链接、Markdown 导入和群组。分享链接只把名称、职责和可携带的记忆填到草稿，由用户选择本机模型并确认创建。设置可停用本机 Bots 的新消息和值守，保留旧聊天。新建主聊天可选确认，保存模型配置后下一份新聊天使用该模型。

2026-11-26 用户补充群聊和右键交互参考。从侧栏点群组进入聊天，首次使用第一个启用的成员回复，之后记住该群组的选择。可改为所有 Bots 或仅在被提及时回复。显式提及覆盖默认回复对象，`@everyone` 发给全部已启用成员。每位 Bot 保有该群的独立会话，停止单条回复只处理对应的队列消息或回合。

2026-11-26 用户要求支持 Bot 在群里互相提问。群组请求带上近期同群消息和已完成的回复。用户让当前 Bot 问另一位成员时，由当前 Bot 调用 `bot_group_ask`，Host 核对本轮群消息和成员归属，问题和回复都显示在原群。每位 Bot 对同一条用户消息可以向同一成员提问一次，收到 Bot 提问的成员直接回答，下一次转问由新的用户消息发起。Bot 会话的 AMO MCP 只提供这项群聊工具。

群组和 Bot 可在侧栏重命名、标记未读或删除。群组菜单可管理成员，Bot 菜单可打开该 Bot 的设置、暂停接收新请求或复制默认工作目录。删除前检查运行中的回合与排队消息。删除群组保留成员各自的会话，删除 Bot 清除配置和记忆，保留已有回复和会话的只读记录。

## Bot 技能设置

> 状态：已实现。2026-11-26 用户确认了共有与专用技能入口、添加弹窗和插件技能分配方案。

- **共有技能**放在「设置 → 工具与自动化 → Bots → 通用设置」，位于现有开关下方。列表显示已设置的技能，提供「添加技能」和移除操作，通过「保存共有技能」统一提交。说明「本机现有和以后新建的 Bot 都会继承」。共有技能从本机全局技能中选取。
- **单个 Bot**在「设置 → 工具与自动化 → Bots → 选中 Bot → 访问与技能」配置。界面列出继承的共有技能，可跳转到「管理共有技能」。添加或移除此 Bot 的专用技能后自动保存。
- **添加技能**共用可搜索、多选的选择器，按「本机全局」「项目技能」「插件内置」分组，可按来源筛选。每项展示技能名称、来源与简介，可打开对应的 `SKILL.md`。点击「添加」将所选技能加入列表。单个 Bot 可以选本机全局技能、所选项目的技能，以及当前渠道能使用的插件技能。技能展览负责查找和浏览。
- **插件内置技能**由 Codex、Claude Code 安装与启用，AMO 按技能分配。选择器展示插件名和适用渠道。先核对配置所选渠道和工作目录的实际技能列表，再开放勾选。已确认停用的插件显示「插件未启用」，仅在缓存里发现的技能显示「未确认可用」。按渠道、插件标识和技能标识保存引用，插件升级后按新版本解析。共有技能从本机公共 Agent 目录 `~/.agents/skills` 选取，单渠道插件的技能在对应 Bot 下单独添加。项目的公共 Agent 技能适用于 Codex、Claude 和 DSH。
- **生效规则**采用「共有技能 + 此 Bot 专用技能」，同一技能只生效一次。同名但来源不同的技能分别展示。Host 在创建 Bot 聊天时按实际目录解析技能，把可用技能的 `SKILL.md` 路径写入会话上下文。模型在任务匹配时读取说明。不可用的技能保留在设置中，新聊天会提示哪些技能没加载。已有主聊天可通过「新建主聊天」使用新配置。Bot 的执行权限照原有设置执行。

验收时建两个 Bot，共有技能各继承一次，专用技能只关联到对应 Bot。验证新建 Bot 自动继承、移除共有项后的结果，以及换运行时或工作目录导致技能不可用时的提示。用实际新建聊天核对配置是否加载。

## 单个 Bot 的设置与资料目录

2026-11-26 用户确认在 AmoStudio 自己的设置窗口实现预览。右侧显示 Bot 名称和接收消息开关，分为概览、运行配置、角色与记忆、自动化、访问与技能、通知。现有的模型、权限、默认项目、技能、Webhook 和聊天记录放在各自分区。2026-11-27 改为自动保存已有 Bot 的设置，底部保留主聊天操作和保存状态。新建主聊天等自动保存完成后使用新配置。

- 资料目录为 Studio 数据目录的 `bots/<Bot ID>/`，包含 `SOUL.md`、`MEMORY.md` 和 `memory/`。Host 启动时为旧 Bot 从数据库补齐文件，已存在的 Markdown 保留原文。新聊天读职责和长期记忆，`@Bot` 新开聊天照常使用发起会话的项目或工作树。自动保存核对正在编辑的文件。遇到外部修改时保留磁盘内容，界面保留草稿并提供重试和放弃操作。重命名和新建主聊天沿用这份目录。
- 巡视复用值守，用户填写指令并保存计划后定时开一个新的 Bot 聊天。长期未活动按最近会话更新时间显示在概览。
- 2026-11-27 用户要求默认每天整理并写入长期记忆，并按 Orca 1.4.274 的方式用模型提取。Codex 和 Claude Bot 默认在本机时间凌晨 3 点整理一次，可在 Bot 设置的「自动化」改时间、关闭或手动运行。切换到 DSH 暂停整理，切回支持的渠道时沿用旧计划的开关和时间。使用该 Bot 的模型按批回顾未处理的直接聊天、对应回复和已有记忆。模型在无工具的独立回合返回草稿，Host 核对用户原话并去重后追加到 `MEMORY.md`。失败保留未处理消息供重试。保留现有记忆原文，旧的 `memory/自动整理.md` 可继续查看。
- 「允许同群 Bot 提问」保留既有默认，可按 Bot 关掉。Bot 需要授权、完成或失败时，可以分别开启 Studio 内提醒。连接器继续使用现有 Webhook。

## 实现

1. **Bot 配置和请求记录。** `protocol` 定义配置和请求类型，Host 保存 Bot ID、名称、职责、模型配置、启用状态及记忆。每次请求持久关联发起任务、发起会话和审查会话。首版记忆由用户编辑，启动审查时提供当前内容。Bot 配置与记忆按 Studio 数据目录保存。
2. **从任务提及 Bot。** 一条消息可选多位 Bot，本机任务主会话默认先将整条原话交给当前 AI。需要联系时，AI 用对应收件人的提及编号分别调用 `bot_ask`，补上讨论背景。Host 从同一条提及记录核对发起会话、收件人和各自的目标聊天。点某个 Bot 的头像可改它的目标聊天；取消「由当前 AI 转交」后，Studio 直接发给选中的各位 Bot。
3. **执行权限。** 2026-11-26 用户要求 Bot 使用 AMO 的权限卡片。创建聊天时保存所选渠道的执行权限。默认和旧配置沿用只读策略，Codex 和 DSH 使用只读沙箱，Claude 使用只读工具列表。选用其他权限时按渠道支持的模式执行。追问、恢复及分支沿用原会话权限。
4. **进度和回传。** 请求关联具体 Bot 回合，审核员聊天显示发起任务名称和问题。AI 派发的请求结束时，Host 将回信放进原会话的持久收件箱，当前 AI 可接着回复用户。直接发送的结果显示在请求卡。两种模式的追问都沿用产生结论的聊天。

定时从「值守」触发。群组把请求投给人选定的成员，各成员在自己的群组聊天中执行。通用 Webhook 由 AMO 中转接收，在对应账号的设备上运行，默认只向外返回状态。用户可以从已完成的 Bot 结论创建独立 worktree 执行任务。

## 验收

- 在隔离 Electron 实例中配置「审核员」，从任务会话 `@` 它。核对只启动一个审查会话、使用正确项目或 worktree，结果回到原会话且可以打开追问。
- 模拟同一请求重试、Host 重启和停止或失败，核对运行记录可恢复，审查会话和完成回传各只出现一次。
- 验证首次启动、追问和恢复的只读约束，覆盖写文件、提权和可写工具调用；检查正常消息和既有 `@` 子会话回归。按项目要求检查界面截图，并用真实 Codex 在临时 Git 仓库完成一次只读审查。

## 完整迁移范围评估

以本机 Orca 1.4.274 为参考，先实现可长期管理的 Bot，再加接单渠道。只读「审核员」可作为验证整条链路的第一个模板。

| 能力 | AMO 落地 |
|---|---|
| Bot 工作台与聊天生命周期 | 每个 Bot 有头像、独立的职责、记忆、模型和执行设备。头像可以上传图片或使用默认头像。侧栏可打开主聊天、历史和工作记录。`@Bot` 默认投递到主聊天，也能选已有聊天或新开。支持重置主聊天、保留旧历史与记忆、手动删除普通聊天。草图里的每请求新建审查会话对应「新开」选项。 |
| 派工、群组和人工接管 | 复用 AMO 主控、任务、worktree、问题和验收。Bot 群聊需要补成员、消息和回复路由，工作台汇总待处理决定、执行进度和交付。 |
| 模板、记忆和自动化 | 复用值守和运行记录，补每个 Bot 的模板、日程、事件触发、运行历史及记忆整理。默认规则和审查记录分别保存，重置聊天不清空 Bot 记忆。 |
| 外部接单与回传 | 复用 AMO 中转设备通道，新增外部连接器服务和接入授权。Orca v1.4.274 的仓库提供 MIT 桌面代码及连接器协议，Slack、Linear、GitHub 的托管连接器服务需在 AMO 侧实现等价能力。邮件、日历和 Webhook 按各自入口接入。 |
| 跨设备与旧 Bot 导入 | 复用 AMO 的远程会话和移动端基础，新增 Bot 列表、待确认、对话和运行记录。设置可读取原 Bot 的 `SOUL.md` 和 `MEMORY.md`；旧聊天与自动化需单独核对格式和引用，第三方账号和连接重新授权。 |

## Plane 手动接单

2026-11-26 用户同意先走单项目试点。从 Studio 的团队工作项选择「交给 Bot」，选只读 Bot 和有提交的本地 Git 项目。Bot 在所选项目只读分析，Studio 把分析交给独立工作树里的执行会话。会话读取原单，提交摘要和验证证据。用户在 Studio 验收通过后，Host 用接单时的 Plane 账号写回原单评论。首版由人发起，Plane 状态和执行人照常由团队管理。2026-11-27 起，开工前要先确认 Bot 的计划，交付后可以让 Bot 对照计划检查，见 [`done/bot-work-loop.md`](done/bot-work-loop.md)。

本机以 Plane 服务器、项目、账号和工作项识别已有请求。回写用验收结果 ID，Plane 覆盖层持工作项行锁查找或创建评论。部署较早的覆盖层明确不支持 Bot 评论时，Studio 可用同一账号通过 Plane 标准评论接口回写。Studio 持久化发起记录，响应不明时只核对原单上的已有评论，避免重复创建。Host 重启后继续处理尚未确认的回写。原单关联变更、接单账号切换或交付退回时暂停回写。
