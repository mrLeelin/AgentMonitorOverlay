# AMO Studio 常驻 Bot

> 状态：进行中。2026-11-25 用户要求迁移 Orca Bots，并在主工程的独立分支提交。实现分支为 `feat/studio-bots`，以本机 Orca 1.4.274 为行为参考。

## 首版体验

在「设置 → 工具与自动化 → Bots」创建或配置「审核员」，选渠道和型号，通过滑杆调整推理强度，通过卡片选择执行权限，填写审核职责和可复用的记忆。回到本机任务会话，输入 `@` 并选择「审核员」，再发送审核要求。原会话显示一条可打开的审核记录，包含进度和结论。点击记录进入同一审查会话看完整结果、停止或继续追问。

审核员默认在发起会话的实际工作目录里检查，以便看到用户指定的 worktree 里的未提交改动。需要审核另一个工程时，从 Studio 已登记的项目中选取。结论按问题严重程度列出文件、行号和证据，并注明检查范围和未验证项。

2026-11-26 用户给出侧栏和创建交互参考。Bots 放在左栏独立区域，主聊天由 Bot 自己的入口打开，工作者仍是可执行的项目任务。折叠、排序和筛选保存在当前窗口。加号支持空白、模板、Orca 分享链接、Markdown 导入和群组。分享链接只把名称、职责和可携带的记忆填到草稿，由用户选择本机模型并确认创建。设置可停用本机 Bots 的新消息和值守，保留旧聊天。新建主聊天可选确认，保存模型配置后下一份新聊天使用该模型。

2026-11-26 用户补充群聊和右键交互参考。从侧栏点群组进入聊天，首次使用第一个启用的成员回复，之后记住该群组的选择。可改为所有 Bots 或仅在被提及时回复。显式提及覆盖默认回复对象，`@everyone` 发给全部已启用成员。每位 Bot 保有该群的独立会话，停止单条回复只处理对应的队列消息或回合。

群组和 Bot 可在侧栏重命名、标记未读或删除。群组菜单可管理成员，Bot 菜单可打开该 Bot 的设置、暂停接收新请求或复制默认工作目录。删除前检查运行中的回合与排队消息。删除群组保留成员各自的会话，删除 Bot 清除配置和记忆，保留已有回复和会话的只读记录。

## 实现

1. **Bot 配置和请求记录。** `protocol` 定义配置和请求类型，Host 保存 Bot ID、名称、职责、模型配置、启用状态及记忆。每次请求持久关联发起任务、发起会话和审查会话。首版记忆由用户编辑，启动审查时提供当前内容。Bot 配置与记忆按 Studio 数据目录保存。
2. **从任务提及 Bot。** 一条消息可选多位 Bot，本机任务主会话默认先将整条原话交给当前 AI。需要联系时，AI 用对应收件人的提及编号分别调用 `bot_ask`，补上讨论背景。Host 从同一条提及记录核对发起会话、收件人和各自的目标聊天。点某个 Bot 的头像可改它的目标聊天；取消「由当前 AI 转交」后，Studio 直接发给选中的各位 Bot。
3. **执行权限。** 2026-11-26 用户要求 Bot 使用 AMO 的权限卡片。创建聊天时保存所选渠道的执行权限。默认和旧配置沿用只读策略，Codex 和 DSH 使用只读沙箱，Claude 使用只读工具列表。选用其他权限时按渠道支持的模式执行。追问、恢复及分支沿用原会话权限。
4. **进度和回传。** 请求关联具体 Bot 回合，审核员聊天显示发起任务名称和问题。AI 派发的请求结束时，Host 将回信放进原会话的持久收件箱，当前 AI 可接着回复用户。直接发送的结果显示在请求卡。两种模式的追问都沿用产生结论的聊天。

定时从「值守」触发。群组把请求投给人选定的成员，各成员在自己的群组聊天中执行。通用 Webhook 由 AMO 中转接收，在对应账号的设备上运行，默认只向外返回状态。用户可以从已完成的 Bot 结论创建独立 worktree 执行任务。

## 验收

- 在隔离 Electron 实例中配置「审核员」，从任务会话 `@` 它。核对只启动一个审查会话、使用正确项目或 worktree，结果回到原会话且可以打开追问。
- 模拟同一请求重试、Host 重启和停止或失败，核对运行记录可恢复，审查会话和完成回传各只出现一次。
- 验证首次启动、追问和恢复的只读约束，覆盖写文件、提权和可写工具调用；检查正常消息和既有 `@` 子会话回归。按项目要求检查界面截图，并用真实 Codex 在临时 Git 仓库完成一次只读审查。

## 完整迁移范围评估

以本机 Orca 1.4.274 为参考，先实现可长期管理的 Bot，再加接单渠道。只读「审核员」可作为验证整条链路的第一个模板。

| 能力 | AMO 落地 |
|---|---|
| Bot 工作台与聊天生命周期 | 每个 Bot 有头像、独立的职责、记忆、模型和执行设备。头像可以上传图片或使用默认头像。侧栏可打开主聊天、历史和工作记录。`@Bot` 默认投递到主聊天，也能选已有聊天或新开。支持重置主聊天、保留旧历史与记忆、手动删除普通聊天。草图里的每请求新建审查会话对应「新开」选项。 |
| 派工、群组和人工接管 | 复用 AMO 主控、任务、worktree、问题和验收。Bot 群聊需要补成员、消息和回复路由，工作台汇总待处理决定、执行进度和交付。 |
| 模板、记忆和自动化 | 复用值守和运行记录，补每个 Bot 的模板、日程、事件触发、运行历史及记忆整理。默认规则和审查记录分别保存，重置聊天不清空 Bot 记忆。 |
| 外部接单与回传 | 复用 AMO 中转设备通道，新增外部连接器服务和接入授权。Orca v1.4.274 的仓库提供 MIT 桌面代码及连接器协议，Slack、Linear、GitHub 的托管连接器服务需在 AMO 侧实现等价能力。邮件、日历和 Webhook 按各自入口接入。 |
| 跨设备与旧 Bot 导入 | 复用 AMO 的远程会话和移动端基础，新增 Bot 列表、待确认、对话和运行记录。设置可读取原 Bot 的 `SOUL.md` 和 `MEMORY.md`；旧聊天与自动化需单独核对格式和引用，第三方账号和连接重新授权。 |

相关基线见 [Orca Bots 文档](https://orca.dev/docs/bots)、[v1.4.274 连接器服务边界](https://github.com/stablyai/orca/blob/v1.4.274/cloud/README.md) 和 [AMO 远程会话方案](done/remote-session.md)。

待补的能力包括 Slack、Linear、GitHub 原生连接器，Google 邮件和日历，跨设备 Bot 群组与手机端 Bot 页面，自动记忆整理、主动建议，以及 Orca 的旧聊天、自动化和模板批量导入。Webhooks 需要兼容的 AMO 中转版本，团队中转上线属于独立发布步骤。
