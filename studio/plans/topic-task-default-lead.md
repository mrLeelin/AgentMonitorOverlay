# 有主控的专题里新建任务：默认归主控，或交给主控安排（2026-11-17）

> 状态：已定，待实施。2026-11-17 用户按建议定了下面「用户定的」3 条，还没动手；界面部分等用户正在做的 Goal 改动提交后再做。来源：2026-11-17 梳理 Free 专题主控卡住、沟通慢的原因。

## 为什么

Free 专题（2026-11-17）里，主控正带着下级「核对 DarkEvilSlotGame…」做 Free 的配置和代码。这时人在专题里另建了一个任务：「我记得 Project/TuiBiji_BackUp 分支中 Free 有一个 Ui 界面，把那个也移植过来」。结果：

- 这个任务没有直属主控，主控看不见它，也管不了它。主控不能认领不归它管的任务（`features/tasks/service.ts` 的 `setManager`）；第一次分配只能由人或专题会话来做。
- 两个任务同时改 `DarkEvilSlotFreeHandler.cs`，都把对方的改动当成「外部并发修改」。下级为此多提了一个决定、多做了一次复核，交付也被拖住。
- UI 任务给主控发了 5 封留言想协调，主控一封都没看到。11-17 改过之后，下级给**直属**主控的留言会送进主控的会话；但这个任务不是下级，仍然送不到。

现状：

- 三个新建入口（新建任务页、画布上新建、快速开始）都走 `ui/src/newtask/draft.ts` 的 `submitDraft`，只传 `lead`，不传直属主控。
- Host 的建任务接口本来就接受 `managerTaskId`，并会检查它（`features/tasks/service.ts` 的 `createTask` → `checkManager`：必须是同专题里有效的主控，且不能成环）。
- 已有任务可以在任务页的「直属主控」里设置（`ui/src/task/TaskManagement.tsx`），但设置之后主控收不到任何提示。

## 已定的原则（不改）

- 2026-11-07（`plans/done/lead-management.md`）：
  - 管理归属必须持久保存，由人明确设置，不能按同专题或画布位置推断；
  - 第一次分配由人或专题会话做；
  - 主控只能在自己的下辖范围里转交，不能认领。
- 本方案守住这一条：默认值摆在新建界面上，人看得到、能改，提交时由人决定；不在后台按专题自动归属。

## 用户定的（2026-11-17，按建议）

1. A、B 两种都做，「交给主控安排」作主按钮。
2. 专题有多个根主控时不设默认。
3. 已经存在、没有主控的任务，只在画布上提示人，不通知主控。

## 做法

### A. 新建时默认归主控

1. 在专题里新建任务时，界面上加一栏「直属主控」：
   - 专题里只有一个根主控（本身没有直属主控的主控任务）时，默认选它，可以改成「不归主控」；
   - 有多个根主控时，全部列出来让人选，默认不选。
2. 提交时把 `managerTaskId` 带给 `POST /api/tasks`。
3. 归属生效后，给这个主控发一条通知，用途是通知，主控空闲时送进去：「【新下级任务】「…」已归你管理：<第一句话>。它的问题会交给你，交付由你验收。」
   - 主控自己拆出来的任务不发，它已经知道；
   - 人之后在任务页把已有任务分给主控时，也发同样一条。
4. 新任务照常马上开始，和主控拆出来的下级一样：问题先交给主控，交付由主控验收。人仍然可以直接跟它说话，但人发的工作消息会让它已验收的交付失效（现有规则）。

### B. 「交给主控安排」

1. 在有主控的专题里，输入框多一个「交给主控安排」按钮。它不建新任务，而是把这句话作为人发给主控的消息送进主控会话，用途是工作，和人直接发给主控的消息一样。
2. 由主控决定是新建下级，还是交给已有的下级。新建时用 `task_plan_propose`，可以加依赖，排在正在改同一批文件的任务后面。
3. 好处是主控掌握全局，能避免同一个文件被并行修改；代价是多一跳，要等主控跑一轮才开工。

建议两种都做：专题有主控时，「交给主控安排」作为主按钮，旁边保留「新建任务」，并默认归主控。

## 影响范围

- **界面：** `ui/src/newtask/NewTaskPage.tsx`、`QuickStart.tsx`、`draft.ts`，要加「直属主控」一栏、默认值和「交给主控安排」按钮。这几个文件现在有用户未提交的 Goal 改动，要等那部分提交后再动，避免冲突。
- **Host：** `features/tasks/service.ts`，人设置归属时给新主控发通知，投递复用 `features/orchestration` 的通知队列。「交给主控安排」复用现有的发消息接口，不需要新接口。

## 风险

- **人想自己单独跟的小任务被默认归了主控。** 默认值放在显眼位置，可以改。
- **主控收到「新下级任务」会醒一轮。** 每个任务只发一次。
- **专题里有多个根主控。** 不设默认，免得选错。

## 验证

单测：
- 人建任务时带上 `managerTaskId`，主控收到一条通知；主控自己拆出的任务不发；
- 人在任务页把已有任务分给主控，也收到一条。

e2e：
- 在有主控的专题里新建任务，界面默认显示这个主控，并能改成不归主控；
- 「交给主控安排」把这句话送进主控会话。
